# Faro はじめてガイド

[English](guide.en.md)

Faro は、アプリの画面を Figma のように描き、その部品をコード(C# または Java)のクラスやメソッドに「紐付け」て動かすエディターです。このガイドでは、インストールから、画面を作ってコードとつなぎ、動かして確かめるまでを順に説明します。

機能の詳しい説明は [開発者向けドキュメント](development.md) と [仕様書](../ui-editor-tool-spec.md) にあります。

---

## 1. インストール

[GitHub Releases](https://github.com/thesilver0913/faro-editor/releases) から、お使いの OS のファイルを入れます。

| OS | ファイル | 補足 |
|---|---|---|
| Windows | `Faro-<版>-win-x64-setup.exe` | .NET 10 SDK がなければ、インストール中に取ってくるか選べます。Program Files に入れるときは、最初の画面で「すべてのユーザー用にインストール」を選びます |
| Linux | `Faro-<版>-linux-x64.deb` / `.tar.gz` | .deb は `sudo apt install ./Faro-….deb`。.NET 10 SDK がなければ入れます |
| macOS | `Faro-<版>-osx-arm64.pkg`(Apple シリコン)/ `osx-x64.pkg`(Intel) | 公証していないため、初回は右クリック › 開く |

**必要なもの**

- **C# のプロジェクト**:.NET 10 SDK(インストーラーが用意します)
- **Java のプロジェクト**:JDK 21 と Maven。Faro の「環境設定 › 部品」からワンクリックで入れられます
- **AI チャット**(任意):環境変数 `ANTHROPIC_API_KEY`(Claude)または `OPENAI_API_KEY`。キーは Faro の設定には保存されません

## 2. はじめての起動

初回は言語(English / 日本語)とテーマを選ぶ画面が出ます。あとから「編集 › 環境設定」で変えられます。

続いてウェルカム画面が開きます。

![ウェルカム画面](images/welcome.png)

- **新規プロジェクト…**:テンプレートと言語を選んで作ります
  - テンプレート:`Sample`(画面・部品・紐付けの入った見本)か `Empty`(空)。最初は **Sample** がおすすめです
  - 言語:`C# (Avalonia)` か `Java (JavaFX)`
- **フォルダを開く…**:既存のプロジェクトを開きます(Faro のプロジェクトでないフォルダは、確認のうえ初期化します)
- **最近のプロジェクト**:クリックで開きます

![新規プロジェクト](images/new-project.png)

新しいプロジェクトは**名前なし(Untitled)**で始まります。気に入ったら「ファイル › 保存」(Ctrl+S)で名前と場所を決めてください(既定の場所は `ドキュメント/Faro`)。

### プロジェクトの信頼

初めて開くフォルダでは「信頼する / 制限モード」を聞かれます。信頼すると、プロジェクトのコードのビルド・実行、言語サーバー、プレビューが使えます。知らない人から受け取ったプロジェクトは、中身を確かめるまで制限モードで開くのが安全です(あとで「ファイル › プロジェクトを信頼…」で切り替えられます)。

## 3. 画面の見方

![メイン画面](images/main-window.png)

| 場所 | 役割 |
|---|---|
| 左上 **エクスプローラー** / **ソース管理** | プロジェクトのファイル一覧 / Git の変更・コミット |
| 左下 **レイヤー** / **パーツ** | 画面の Node(部品)の木 / 追加できる部品の一覧 |
| 中央上 **キャンバス** | 画面を描く場所。クリックで Node を選び、ドラッグで並べ替え |
| 右 **インスペクター** | 選んだ Node の大きさ・並べ方・見た目・紐付けを編集 |
| 中央下 **コード** | C# / Java のコードエディタ(補完・エラー表示つき) |
| 中央下 **コンソール** | 問題・出力・AI チャット・履歴・デバッグのタブ |

パネルは「ウィンドウ」メニューで前面に出せます。並びを崩したら「ウィンドウ › レイアウトを初期化」。

**迷ったら Ctrl+Shift+P**(コマンドパレット)。メニューの操作を名前で探して実行できます(日本語でも英語名でも探せます)。

## 4. 画面を作る

### Node を置く

「パーツ」タブから部品をキャンバスへドラッグするか、クリックで選んでいる Node の中に追加します。

![パーツ](images/parts.png)

- **コンテナ**:`Stack`(縦・横に並べる)、`Wrap`(折り返し)、`Grid`(行と列)、`Overlay`(重ねて四隅や中央に固定)
- **コントロール**:`Button`、`TextInput`、`Text`、`Image`、`CheckBox`(チェックボックス)、`Switch`(スイッチ)、`Slider`(スライダー)、`Select`(選択肢のドロップダウン)、`Progress`(進捗バー)、`Divider`(区切り線)、`Spacer`(隣の部品を押し広げる空きスペース)、`Script`(見た目も動きもコードで作る部品)

Faro は**絶対座標を使いません**。位置は「どのコンテナに、どの順で入れるか」と、次の設定で決まります。

### 大きさと並べ方(インスペクター › レイアウト)

- **幅・高さ**:`Fill`(いっぱいに広がる)/ `Hug`(中身に合わせる)/ `Fixed`(数値で固定)
- **最小・最大**、**外側の余白**(margin)、コンテナの**間隔**(gap)と**内側の余白**(padding)
- **揃え**・**並べ方**(`SpaceBetween` で両端に広げる)・**個別の揃え**(その Node だけ位置を変える)
- 余白は `8`(全辺)、`8 16`(上下 左右)、`8 16 8 16`(上 右 下 左)と書けます

### 見た目(色と文字)

インスペクターの「見た目」で、Node の塗りと文字色(`#6750A4` や `Red`)、フォント・文字サイズ・行の高さ・太さを指定できます。**ホバー / 押下 / 無効**の行では、その状態のときだけの塗りと文字色を指定できます(押下はボタン)。空欄の項目はデザイン言語の見た目のままです。コンポーネントのマスターやバリアントに付ければ、インスタンスにもそのまま乗り、インスタンス側で上書きもできます。

### トークン(Figma の変数)

「ファイル › プロジェクトのデザイン…」の「トークン」に、1 行に 1 つ `名前 = 値` で書きます。

- 大きさ:`space.m = 16` → 余白や大きさの欄に `$space.m`
- 色:`color.primary = #6750A4` → 塗りや文字色の欄に `$color.primary`
- 文字スタイル:`text.title.fontSize = 22`、`text.title.fontWeight = Bold`、`text.title.fontFamily = Inter`、`text.title.lineHeight = 28` → 「文字トークン」で `$text.title` を選ぶ(Node 側で個別に指定した項目はそちらが優先)

トークンの値を変えるだけで、全画面の見た目がそろって変わります。

### デザイン言語

同じダイアログで、デザイン言語と、基調色(シードカラー)・ライト/ダークを選びます。

| デザイン言語 | 見た目 |
|---|---|
| Fluent | Windows 風(Avalonia の標準) |
| Material 3 | Google の Material 3 Expressive。インスペクターの「Material 3」欄でボタンの種類(Filled / Tonal / Outlined…)なども選べる |
| Cupertino | iOS 風 |
| Neumorphism | 面から柔らかく浮き出る形 |
| NeoBrutalism | 明るい色、太い輪郭、硬い影 |
| Simple | 落ち着いた無彩色(shadcn/ui 風) |
| Carbon | IBM のデザイン。角張った形、下線付きの入力欄 |
| Clay | ぷっくりした粘土のような形とパステル色 |
| Retro | Windows 95 風の立体的な縁取り |

どの言語も色はシードカラーから作ります。Material 3 以外の言語では、インスペクターの言語名の欄で、ボタンの**種類**(Filled / Tonal / Outlined / Text)とコンテナの**面**(カード:面から浮かせる/くぼみ:沈める)を選べます。言語を切り替えても設定はそのまま引き継がれます。

### 編集の基本

- 取り消し / やり直し:Ctrl+Z / Ctrl+Y(最後に触ったのがキャンバスなら UI の編集、コードならコードの編集が対象)
- コピー・貼り付け・複製:Ctrl+C / Ctrl+V / Ctrl+D(紐付けも一緒に複製されます)
- 削除:Delete、並べ替え:Alt+↑ / Alt+↓、右クリックで「コンテナで囲む」なども
- **ツール列**:キャンバスの左端に、追加・削除・上へ・下へ・揃えが並びます(Adobe のツールパネルのように、右下に印のあるボタンは押すと仲間の道具が開き、最後に使ったものが表に出ます)
- **揃え**:ツール列の揃え(左・中央・右 / 上・中央・下)。横並びの中で「右揃え」を押すと、前にスペーサーが入って右端に寄ります。縦並びの中の横方向は、その Node だけの揃えになります。重ね置きの中では、固定する位置が変わります
- **文字の編集**:キャンバスの文字・ボタン・入力欄をダブルクリックすると、その場で書き換えられます(Enter で確定、Esc で取り消し)
- コンソールの「履歴」タブで、UI の編集を一覧から選んで戻れます

![履歴](images/history.png)

## 5. コンポーネント(再利用する部品)

何度も使う部品(ボタン、一覧の行など)は**コンポーネント**にします。エクスプローラーの `UI` フォルダを右クリック › 新しいコンポーネント… で作り、キャンバスでマスターを編集します。作ったコンポーネントは「パーツ」の「コンポーネント」に並び、画面に置けます。

- **マスター**を編集すると、使っている場所(**インスタンス**)に「同期待ち」が付きます。キャンバスの同期ボタン(🔄)で反映します。勝手には変わりません
- インスタンスごとに文字などを**上書き**できます(インスペクター › 上書き)
- **バリアント**:インスタンスを選んで「コンポーネント › 新しいバリアント…」で、同じ部品の別の版(例:Outlined)を作れます。インスタンスは「バリアント」でどの版を使うか選びます
- **繰り返し(リスト)**:インスタンスで「繰り返し」をオンにすると、一覧の 1 行として扱われます。キャンバス用の見本の行(モック行)も書けます

## 6. コードとつなぐ(紐付け)

Faro は画面からコードを生成しません。画面の部品を、コードの**クラスのメンバー**に紐付け、実行時に Faro のランタイムがつなぎます。

### クラスを用意する

`Source/` にクラスを書きます。自分で書いても、コンソールの **AI チャット**に「注文を追加する Submit メソッドを持つ OrderService を作って」のように頼んでも構いません(生成されたコードは、承認するまで保存されません)。

- C#:`FaroObject` を継承すると、値の変化が画面に伝わります
- Java:`FaroObject` を継承し、変えたら `changed("プロパティ名")` を呼びます
- クラスの生き方は属性で決めます(既定は画面ごとに作られる `ScreenScoped`。アプリで 1 つなら `[FaroLifetime(Lifetime.Singleton)]`、保存するなら `Persistent = true`)

### 紐付けを追加する

Node を選び、インスペクター下の「紐付け」で追加します。

![紐付け](images/inspector-bindings.png)

- **イベント**(`Click`、`Changed`):押されたらメソッドを呼ぶ。`Navigate:Screen.Detail` で画面遷移
- **プロパティ**(`Text`、`Checked`、`Value`、`Selected`、`Visible`、`Enabled`…):値を表示する(`OneWay`)/ 入力を書き戻す(`TwoWay`)。`Select` の選択肢は `Options` に一覧を紐付けても変えられます
- **書式**:`¥{0:N0}` のように表示形式を付けられます(`{0:N0}` 3 桁区切り、`{0:F2}` 小数 2 桁)
- **リスト**:繰り返しのインスタンスに `Items` を紐付けると、一覧のデータの数だけ行が並びます。行の中の Node は、行のデータ(例:`Order.Name`)に紐付けます
- **行の選択**:行(コンテナ)の `Click` に、引数 1 つのメソッド(`Open(Order order)`)を紐付けると、押した行のデータが渡ります
- **画面に値を渡す**:コードから `FaroApp.Navigate("Detail", order)`。遷移先の紐付けがその値を使います

![行をクリックして詳細へ](images/app-detail.png)

名前を間違えたり、コードの名前を変えて紐付けが切れたりすると、Node に**赤いバッジ**が付き、「問題」タブに並びます。インスペクターに近い名前の候補が出るので、クリックで直せます。C# では、Faro のコードエディタで名前を変えて保存すると、紐付けも自動で追従します。

## 7. 確かめる

### キャンバスで

- **プレビュー**:ボタンや入力を実際に操作できます(画面遷移も動きます。コードは動きません)
- **データ**(C#):最後のビルドのコードを使い、紐付けた本物の値でキャンバスを表示します

![データのプレビュー](images/data-preview.png)

- **並べて比べる**:「1 枚で表示 ▾」から「全サイズを並べる」(Phone / Tablet / Desktop)や「ライトとダークを並べる」

![ライトとダーク](images/compare-light-dark.png)

### 実行する

キャンバスの **実行**(F5)でアプリが別ウィンドウで起動します。出力とビルドエラーはコンソールへ。C# ではコードの変更がその場で反映され(ホットリロード)、UI の変更でアプリが再起動します。Java は Maven でビルドして起動します(変更は再実行で反映)。

### デバッグする

コードの行番号の左をクリック(F9)して赤い点(ブレークポイント)を置き、**デバッグ開始**(F6)。止まると行が黄色くなり、コンソールの「デバッグ」タブに呼び出し履歴と変数が出ます。続行 F8、ステップオーバー F10、ステップイン Shift+F10、停止 Shift+F6。

![デバッガー](images/debugger.png)

デバッガー(C# は netcoredbg、Java は java-debug)は、初めて使うときに自動でダウンロードされます。

## 8. 保存と共有

- **Git**:左上の「ソース管理」タブで、変更の一覧(クリックで差分)、コミット、プル、プッシュができます。画面・コンポーネント・紐付けのファイルは、XML の前に「どの Node が追加・削除・移動され、どの設定が変わったか」をまとめて表示します

![ソース管理](images/source-control.png)

- **Android**:「ファイル › Android APK をビルド」で `dist/` に APK ができます(初回は Android の道具を取ってくるので時間がかかります。Java は Linux のみ)
- プロジェクトはふつうのフォルダです。`UI/`(画面)、`Bindings/`(紐付け)、`Source/`(コード)、`Assets/`(画像)、`faro.json`(設定)

## 9. 困ったとき

| 症状 | 見るところ |
|---|---|
| 赤いバッジが出た | 「問題」タブ。インスペクターの候補から選び直す |
| 実行できない | 「出力」タブのメッセージ。C# は .NET 10 SDK、Java は JDK 21 と Maven(環境設定 › 部品) |
| 補完が出ない | コードの上の「言語サーバー」の状態。Java は初回の読み込みに時間がかかります |
| 変更が反映されない | 「未ビルドのコード変更あり」と出ていたら、実行(F5)で反映されます |
| 落ちた・おかしい | 「ヘルプ › ログフォルダーを開く」。落ちたときはすぐに報告の画面が出ます(「詳細」でエラーの中身を見られます) |
